## Read this first

### The 5 rules that prevent most mistakes

**Rule 1: Use the student account in an Incognito window.** Take the student username and credentials from the lab panel. Your personal Google account can cause conflicts and charges.

**Rule 2: The API key is created in the console, used in Cloud Shell.** Task 1 has a browser part and a Cloud Shell part. Do not skip the `export API_KEY` line, every `curl` after that depends on it.

**Rule 3: Cloud Shell forgets variables.** If it reconnects or you open a new tab, `API_KEY`, `BUCKET_NAME` and `GOOGLE_CLOUD_PROJECT` are gone. Run Step 2 again.

**Rule 4: Check the response before uploading.** A good response contains a `transcript`. If it contains `error`, fix that first. Uploading a broken response file gives no score.

**Rule 5: File names matter, and they are not consistent.** The English files are `speech_request_en.json` and `speech_response_en.json`. The Spanish request is `speech_request_sp.json` but the Spanish response is `response_sp.json` (no `speech_` prefix). Copy the names exactly.

### What you will do

| Task | What |
|------|------|
| 1 | Create an API key |
| 2 | Transcribe an English audio file (`question_en.wav`) |
| 3 | Transcribe a Spanish audio file (`multi_es.flac`) |

Score check: Task 1 alone gives 30/100. Each of Tasks 2 and 3 adds points once its two files are in your bucket.

> **Terms:** An **API key** is a secret token string that lets your `curl` command call a Google API. **Speech-to-Text** turns audio into text. A **bucket** stores files. A **request JSON** tells the API what audio to read and in what language.

## Step 1: Open Cloud Shell

☁️ **CLOUD SHELL**

1. Click the **Activate Cloud Shell** icon (top right of the console, looks like `>_`).
2. Click **Continue** and **Authorize** on any pop-ups.
3. Your prompt should say `cloudshell`.

### 1.1 Enable the API

```bash
# 🔒 COPY AS IS
gcloud services enable speech.googleapis.com
```

The lab usually has this on already, so it may finish instantly. That is fine.

## Task 1: Create the API key

### 1.2 Create the key in the console

🖱️ **CONSOLE**

1. Open the **Navigation menu** (three lines, top left).
2. Go to **APIs & Services > Credentials**.
3. Click **Create Credentials** at the top and choose **API key**.
4. If a form asks for a name or restrictions, leave everything as it is (the name is optional) and click **Create**.
5. A box shows **Your API key**. Click the **copy** icon. Keep this box open until Step 2.1 is done.

> [!IMPORTANT]
> **Which key to use:** use the key you **just created** in this step, not any other. The Credentials page may already list older keys (for example ones the lab created for itself). Ignore those. The key you copy must be the new one from this step.

If you closed the box before copying: on the **Credentials** page, find the new key under **API Keys** (the one with the newest creation date), click **Show key** next to it, and copy it from there.

> [!NOTE]
> Do not add API restrictions to this key. If you did, either remove them or make sure **Cloud Speech-to-Text API** is allowed, otherwise the `curl` calls fail with a `PERMISSION_DENIED` error.

> [!CAUTION]
> 🛑 Never post your API key in a public repo, chat or screenshot.

## Step 2: Save the key and set variables

☁️ **CLOUD SHELL**

### 2.1 Type your API key

> [!IMPORTANT]
> ✏️ **FILL IN: replace `YOUR_API_KEY` with the key you just copied.** Keep the quotes. This is the only place you type your own value in the whole guide.

```bash
# ✏️ FILL IN: paste your key between the quotes
export API_KEY="YOUR_API_KEY"
```

### 2.2 Set the project and bucket, then check everything

🔒 **COPY AS IS** (nothing to change):

```bash
# 🔒 COPY AS IS: safety check
export GOOGLE_CLOUD_PROJECT=$(gcloud config get-value project)
export BUCKET_NAME="${GOOGLE_CLOUD_PROJECT}-speech"
bad=0
case "$API_KEY" in
  YOUR_*|"") echo "❌ API_KEY is not set. Fix it in step 2.1."; bad=1 ;;
esac
[ -z "$GOOGLE_CLOUD_PROJECT" ] && { echo "❌ No project. Run: gcloud config set project PROJECT_ID_FROM_THE_LAB_PANEL"; bad=1; }
if [ "$bad" = "0" ]; then
  echo "✅ All set"
  echo "Project : $GOOGLE_CLOUD_PROJECT"
  echo "Bucket  : $BUCKET_NAME"
  echo "API key : ${API_KEY:0:6}... (hidden)"
fi
```

**Expected:** `✅ All set` followed by your project, bucket and the first 6 characters of your key.

> [!CAUTION]
> 🛑 Do not continue until you see `✅ All set`.

Now confirm the bucket exists:

```bash
# 🔒 COPY AS IS
gcloud storage ls gs://${BUCKET_NAME} >/dev/null 2>&1 \
  && echo "✅ Bucket exists" \
  || echo "❌ Bucket not found. Run the create command in Troubleshooting."
```

Click **Check my progress** for Task 1.

## Task 2: Transcribe English speech

☁️ **CLOUD SHELL**

### 2.3 Create the request file

> [!IMPORTANT]
> The English WAV is **stereo (2 channels)**, so the request must say `audioChannelCount: 2` and `enableSeparateRecognitionPerChannel: true`. Without them the API returns `Must use single channel (mono) audio, but WAV header indicates 2 channels.`

This is one single line on purpose. Long multi-line pastes get garbled in Cloud Shell, a one-line `echo` does not.

```bash
# 🔒 COPY AS IS
echo '{"config":{"encoding":"LINEAR16","languageCode":"en-US","audioChannelCount":2,"enableSeparateRecognitionPerChannel":true},"audio":{"uri":"gs://spls/arc131/question_en.wav"}}' > speech_request_en.json
python3 -m json.tool speech_request_en.json && echo "✅ speech_request_en.json is valid" || echo "❌ File is broken. Run the block again."
```

### 2.4 Call the API

```bash
# 🔒 COPY AS IS ⏳
curl "https://speech.googleapis.com/v1/speech:recognize?key=${API_KEY}" \
  -s -X POST -H "Content-Type: application/json" \
  --data-binary @speech_request_en.json > speech_response_en.json
cat speech_response_en.json
```

**Expected:** JSON with `"transcript"` inside `alternatives`, and a `confidence` number.

> [!CAUTION]
> 🛑 If you see `"error"` or `{}`, do not upload yet. Check the Troubleshooting table first.

### 2.5 Upload both files

```bash
# 🔒 COPY AS IS
gcloud storage cp speech_request_en.json gs://${BUCKET_NAME}/speech_request_en.json
gcloud storage cp speech_response_en.json gs://${BUCKET_NAME}/speech_response_en.json
```

Click **Check my progress** for Task 2.

## Task 3: Transcribe Spanish speech

☁️ **CLOUD SHELL**

### 3.1 Create the request file

The Spanish file is **FLAC**, not WAV, so the encoding changes. The language code becomes `es-ES`.

```bash
# 🔒 COPY AS IS
echo '{"config":{"encoding":"FLAC","languageCode":"es-ES"},"audio":{"uri":"gs://spls/arc131/multi_es.flac"}}' > speech_request_sp.json
python3 -m json.tool speech_request_sp.json && echo "✅ speech_request_sp.json is valid" || echo "❌ File is broken. Run the block again."
```

### 3.2 Call the API

```bash
# 🔒 COPY AS IS ⏳
curl "https://speech.googleapis.com/v1/speech:recognize?key=${API_KEY}" \
  -s -X POST -H "Content-Type: application/json" \
  --data-binary @speech_request_sp.json > response_sp.json
cat response_sp.json
```

**Expected:** JSON with a Spanish `transcript`.

> [!NOTE]
> If the response is `{}` or an error about channels or sample rate, use the fallback request below instead, then run the call above again. I could not test this against the live lab, so use whichever one gives you a transcript.

```bash
# 🔒 COPY AS IS (fallback, only if the first Spanish request gave {} or an error)
echo '{"config":{"encoding":"FLAC","sampleRateHertz":44100,"languageCode":"es-ES","audioChannelCount":2,"enableSeparateRecognitionPerChannel":true},"audio":{"uri":"gs://spls/arc131/multi_es.flac"}}' > speech_request_sp.json
```

### 3.3 Upload both files

Remember Rule 5: the response file here is `response_sp.json`.

```bash
# 🔒 COPY AS IS
gcloud storage cp speech_request_sp.json gs://${BUCKET_NAME}/speech_request_sp.json
gcloud storage cp response_sp.json gs://${BUCKET_NAME}/response_sp.json
```

Click **Check my progress** for Task 3.

## Troubleshooting

| What you see | Why | Fix |
|--------------|-----|-----|
| `❌ API_KEY is not set` in step 2.2 | The `YOUR_API_KEY` placeholder was not replaced | Redo step 2.1, then 2.2 |
| `"error": ... API key not valid` | Key copied wrongly, has a space or newline, or it is an older key and not the one you created | Click **Show key** on the newest key in **APIs & Services > Credentials**, copy it again, redo 2.1 |
| `"error": ... API_KEY_SERVICE_BLOCKED` or `PERMISSION_DENIED` with a restricted key | The key has API restrictions that exclude Speech-to-Text | Open the key, set API restrictions to **Don't restrict key** (or allow Cloud Speech-to-Text API), save, wait 1 minute |
| `"error": ... Cloud Speech-to-Text API has not been used` | API not enabled | Run the enable command in Step 1.1, wait 30 seconds, call again |
| `"error": ... PERMISSION_DENIED` right after creating the key | Key not active yet | Wait 30 to 60 seconds and run the `curl` again |
| Response is just `{}` | API heard no speech with that config | English: confirm `LINEAR16` and `en-US`. Spanish: use the fallback request in 3.2 |
| `Must use single channel (mono) audio, but WAV header indicates 2 channels` | The English WAV is stereo | Add `"audioChannelCount":2` and `"enableSeparateRecognitionPerChannel":true` to the config (already in step 2.3), recreate the request, call again |
| Spanish request uploaded but looks cut off or invalid | A multi-line paste got garbled | Recreate it with the one-line `echo` in 3.1, run `python3 -m json.tool speech_request_sp.json`, upload again |
| `"error": ... bad encoding` or sample rate message | Wrong encoding for the file type | `.wav` uses `LINEAR16`, `.flac` uses `FLAC` |
| `"error": ... Invalid recognition 'config'` | Typo in the JSON | Run `cat speech_request_xx.json`, compare with this guide, recreate |
| `curl: (3) URL using bad/illegal format` | `API_KEY` is empty | Redo Step 2 |
| `gs:///` or `-speech` with nothing before it | `GOOGLE_CLOUD_PROJECT` is empty | Run `gcloud config set project PROJECT_ID_FROM_THE_LAB_PANEL`, then redo 2.2 |
| `BucketNotFoundException` or `404` on upload | Bucket does not exist | `gcloud storage buckets create gs://${BUCKET_NAME}`, then upload again |
| Task 3 stays red but files are uploaded | Wrong response file name | The file must be `response_sp.json`, not `speech_response_sp.json` |
| Check my progress still red | Checker is slow | Wait 20 seconds and click again |
| Variables lost after reconnect | Cloud Shell restarted | Redo Step 2 (your JSON files in the home folder are usually still there) |
