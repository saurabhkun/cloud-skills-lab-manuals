## Read this first

### The 3 rules that prevent most mistakes

**Rule 1: Everything runs in Cloud Shell.** Your prompt should say `cloudshell`.

**Rule 2: Copy ONE block at a time.** Paste, press Enter, read the result, then continue.

**Rule 3: Variables and folders reset.** If Cloud Shell reconnects or you open a new tab, run Step 1 again. If an image path looks like `/monolith-demo/...` with nothing before it, the project variable is empty. Builds must also run from the right folder, so the commands `cd` first.

### What you will do

| Task | What |
|------|------|
| 1 | Clone the website code |
| 2 | Build a Docker image with Cloud Build |
| 3 | Deploy it to Cloud Run |
| 4 | Deploy a new revision with concurrency 1, then back to 80 |
| 5 | Change the homepage and build image version 2.0.0 |
| 6 | Deploy 2.0.0 with zero downtime |

> **What is Cloud Run?** A service that runs your container for you, with no servers to manage. **What is Artifact Registry?** A storage place for your container images.

## Step 1: Open Cloud Shell and set variables

☁️ **CLOUD SHELL**

1. Click the **Activate Cloud Shell** icon (top right of the console, looks like `>_`).
2. Click **Continue** and **Authorize** on any pop-ups.

### 1.1 Type your region

> [!IMPORTANT]
> ✏️ **FILL IN: replace `YOUR_REGION` with your lab's region from Step 0** (for example `us-east4`). Keep everything else. This is the only value you type in the whole guide.

```bash
# ✏️ FILL IN: replace YOUR_REGION with your region, like us-east4  (no spaces, no quotes)
export REGION=YOUR_REGION
```

### 1.2 Set everything else

🔒 **COPY AS IS** (nothing to change):

```bash
# 🔒 COPY AS IS
case "$REGION" in
  YOUR_REGION|"") echo "❌ STOP: replace YOUR_REGION in step 1.1 with your real region, then run 1.1 again." ;;
  *)
    export GOOGLE_CLOUD_PROJECT=$(gcloud config get-value project)
    export IMAGE=${REGION}-docker.pkg.dev/${GOOGLE_CLOUD_PROJECT}/monolith-demo/monolith
    echo "✅ Project: $GOOGLE_CLOUD_PROJECT | Region: $REGION"
    echo "Image path: $IMAGE" ;;
esac
```

**Expected:** a `✅` line with your project and region, and an image path with both filled in (it looks like `us-east4-docker.pkg.dev/your-project/monolith-demo/monolith`).

> [!CAUTION]
> 🛑 If you see `❌`, do 1.1 again. If the project shows blank, run `gcloud config set project PROJECT_ID_FROM_THE_LAB_PANEL` and run 1.2 again.

## Task 2: Build the Docker image

☁️ **CLOUD SHELL**

### 2.1 Create the repository

```bash
# 🔒 COPY AS IS
gcloud artifacts repositories create monolith-demo --repository-format=docker --location=$REGION \
  || echo "ℹ️ If it says the repository already exists, that is fine. Continue."
```

### 2.2 Authenticate Docker and enable the APIs

```bash
# 🔒 COPY AS IS
gcloud auth configure-docker ${REGION}-docker.pkg.dev
```

```bash
# 🔒 COPY AS IS
gcloud services enable artifactregistry.googleapis.com cloudbuild.googleapis.com run.googleapis.com
```

### 2.3 Build

```bash
# 🔒 COPY AS IS
cd ~/monolith-to-microservices/monolith
pwd
gcloud builds submit --tag ${IMAGE}:1.0.0
```

`pwd` should print a path ending in `/monolith`. The build takes a few minutes and should end with `SUCCESS`.

> [!TIP]
> If the build fails with a permission error right after enabling the APIs, wait a minute and run the build again.

Click **Check my progress** for Task 2.

## Task 3: Deploy to Cloud Run

☁️ **CLOUD SHELL**


## Troubleshooting

| What you see | Why | Fix |
|--------------|-----|-----|
| `❌ STOP: replace YOUR_REGION` | The placeholder was not replaced | Do Step 1.1 again with your real region, then 1.2 |
| Image path starts with `/monolith-demo/` | The project variable is empty | Run Step 1 again |
| Build or push fails for the repository | Repository missing or in another region | Run the 2.1 command with **your** region, then rebuild |
| Build fails with a permission error just after enabling APIs | Permissions are still spreading | Wait a minute and run the build again |
| `API has not been enabled` | APIs are off | Run the `gcloud services enable` command in 2.2, wait 30 seconds, retry |
| Build says it cannot find a Dockerfile | Wrong folder | `cd ~/monolith-to-microservices/monolith` first. `pwd` should end in `/monolith` |
| `❌ Homepage not updated` | `index.js.new` is missing or you ran it in the wrong folder | Run the Task 5 first block again from the start |
| Page still shows the old heading | Browser cache or old revision | Hard refresh, and confirm 2.0.0 was deployed in Task 6 |
| Task 4 stays red | Latest revision no longer has concurrency 1 | Redeploy with `--concurrency 1`, click Check, then continue |
| An empty value or `$REGION` is blank | Cloud Shell reconnected | Run Step 1 again |
| Check my progress still red | Checker is slow | Wait 20 seconds and click again |
