## Read this first

### The 5 rules that prevent most mistakes

**Rule 1: Every attempt gets different names.** The zone, cluster name and the four image names change in every lab attempt. Read them from **your** lab panel (Step 0). Never copy names from an old attempt or someone else's guide.

**Rule 2: Everything runs in Cloud Shell.** Your prompt should say `cloudshell`.

**Rule 3: Copy ONE block at a time**, and check the result before moving on. Look for the ✅ and ❌ lines the commands print.

**Rule 4: Check that variables are filled in before you use them.** The most common failure is an empty `ORDERS_IP` or `PRODUCTS_IP`, which makes `curl http://$ORDERS_IP/api/orders` fail with `Could not resolve host: api`. The Task 4 block waits for the IPs and warns you.

**Rule 5: Create the `gcr.io` registry repo before the first build.** In some projects it does not exist. Then Task 1 stays at 0/10 and `gcloud container images list` says `Repository "gcr.io" not found`. Step 2 below fixes this up front.

### 1.1 Type your six values

> [!IMPORTANT]
> ✏️ **FILL IN: replace each `YOUR_...` word with the matching value from your lab panel** (Step 0). Keep the quotes and everything else. This is the only place you type your own values in the whole guide.

```bash
# ✏️ FILL IN: replace each YOUR_... word with the value from your lab panel
export ZONE="YOUR_ZONE"              # ✏️ example: europe-west1-c
export CLUSTER="YOUR_CLUSTER_NAME"   # ✏️ example: fancy-cluster-910
export MONOLITH="YOUR_MONOLITH_NAME" # ✏️ example: fancy-monolith-456
export ORDERS="YOUR_ORDERS_NAME"     # ✏️ example: fancy-orders-620
export PRODUCTS="YOUR_PRODUCTS_NAME" # ✏️ example: fancy-products-439
export FRONTEND="YOUR_FRONTEND_NAME" # ✏️ example: fancy-frontend-445
```

### 1.2 Check them and set the project

🔒 **COPY AS IS** (nothing to change):

```bash
# 🔒 COPY AS IS: safety check
export GOOGLE_CLOUD_PROJECT=$(gcloud config get-value project)
bad=0
for v in ZONE CLUSTER MONOLITH ORDERS PRODUCTS FRONTEND; do
  val="${!v}"
  case "$val" in
    YOUR_*|""|*"<"*|*" "*) echo "❌ $v is not set correctly. Fix it in step 1.1."; bad=1 ;;
  esac
done
echo "$ZONE" | grep -Eq '^[a-z]+-[a-z]+[0-9]+-[a-z]$' || { echo "❌ ZONE '$ZONE' does not look like a zone (example: europe-west1-c)."; bad=1; }
[ -z "$GOOGLE_CLOUD_PROJECT" ] && { echo "❌ No project. Run: gcloud config set project PROJECT_ID_FROM_THE_LAB_PANEL"; bad=1; }
if [ "$bad" = "0" ]; then
  echo "✅ All set"
  echo "Project : $GOOGLE_CLOUD_PROJECT"
  echo "Zone    : $ZONE | Cluster: $CLUSTER"
  echo "Images  : $MONOLITH, $ORDERS, $PRODUCTS, $FRONTEND"
fi
```

**Expected:** `✅ All set` followed by your values. If you see any `❌`, fix step 1.1 and run both blocks again.

> [!CAUTION]
> 🛑 Do not continue until you see `✅ All set`. Cloud Shell forgets variables when it reconnects or you open a new tab. If that happens, run 1.1 and 1.2 again, and re-run the IP block from Task 4.

## Task 2: Cluster and monolith deployment

☁️ **CLOUD SHELL**

The lab asks for 3 nodes. Use `e2-medium` and do not create extra clusters, because the lab warns that excess resources get the project terminated:

```bash
# 🔒 COPY AS IS
gcloud container clusters create $CLUSTER \
  --zone $ZONE --num-nodes 3 --machine-type e2-medium
```

> [!NOTE]
> ⏳ This takes **5 to 10 minutes**. A message like "Cluster is being health-checked (Kubernetes Control Plane is healthy)" is normal. Do not press Ctrl+C and do not run it twice.

Then connect to it and check:

```bash
# 🔒 COPY AS IS
gcloud container clusters get-credentials $CLUSTER --zone $ZONE
kubectl get nodes
```

**Expected:** 3 nodes, all `Ready`.

Deploy and expose the monolith:

```bash
# 🔒 COPY AS IS
kubectl create deployment $MONOLITH --image=gcr.io/${GOOGLE_CLOUD_PROJECT}/${MONOLITH}:1.0.0
kubectl expose deployment $MONOLITH --type=LoadBalancer --port 80 --target-port 8080
```

Wait for the public IP (this waits up to about 5 minutes by itself):

```bash
# 🔒 COPY AS IS ⏳
for i in $(seq 1 30); do
  MONO_IP=$(kubectl get service $MONOLITH -o jsonpath='{.status.loadBalancer.ingress[0].ip}')
  [ -n "$MONO_IP" ] && break
  echo "⏳ Waiting for the monolith IP... ($i/30)"; sleep 10
done
[ -n "$MONO_IP" ] && echo "✅ Open http://$MONO_IP in your browser" || echo "❌ No IP yet. Run this block again in a minute."
```

Open the address (use `http://`) to see the Fancy Store. Click **Check my progress** for Task 2.

## Task 4: Deploy and expose Orders and Products

☁️ **CLOUD SHELL**

Orders uses port **8081** and Products uses port **8082**. Both are exposed on port 80:

```bash
# 🔒 COPY AS IS
kubectl create deployment $ORDERS --image=gcr.io/${GOOGLE_CLOUD_PROJECT}/${ORDERS}:1.0.0
kubectl expose deployment $ORDERS --type=LoadBalancer --port 80 --target-port 8081
```
```bash
# 🔒 COPY AS IS
kubectl create deployment $PRODUCTS --image=gcr.io/${GOOGLE_CLOUD_PROJECT}/${PRODUCTS}:1.0.0
kubectl expose deployment $PRODUCTS --type=LoadBalancer --port 80 --target-port 8082
```

Now save both IPs. This waits for them for up to about 5 minutes and tells you if either is missing:

```bash
# 🔒 COPY AS IS ⏳
for i in $(seq 1 30); do
  export ORDERS_IP=$(kubectl get service $ORDERS -o jsonpath='{.status.loadBalancer.ingress[0].ip}')
  export PRODUCTS_IP=$(kubectl get service $PRODUCTS -o jsonpath='{.status.loadBalancer.ingress[0].ip}')
  [ -n "$ORDERS_IP" ] && [ -n "$PRODUCTS_IP" ] && break
  echo "⏳ Waiting for both IPs... ($i/30)"; sleep 10
done
echo "ORDERS  : $ORDERS_IP"
echo "PRODUCTS: $PRODUCTS_IP"
[ -n "$ORDERS_IP" ] && [ -n "$PRODUCTS_IP" ] && echo "✅ Both IPs found" || echo "❌ An IP is missing. Run this block again in a minute."
```

> [!CAUTION]
> 🛑 Only continue when you see `✅ Both IPs found`. An empty IP makes the next commands fail with `Could not resolve host: api`.

Test them:

```bash
# 🔒 COPY AS IS
curl -s http://$ORDERS_IP/api/orders | head -c 200; echo
curl -s http://$PRODUCTS_IP/api/products | head -c 200; echo
```

Each should return JSON. If you get nothing, wait a minute and try again, because the pods may still be starting. Click **Check my progress** for Task 4.

## Troubleshooting

| What you see | Why | Fix |
|--------------|-----|-----|
| `❌ ... is not set correctly` in step 1.2 | A `YOUR_...` placeholder was not replaced | Fix that line in step 1.1 and run 1.1 and 1.2 again |
| `❌ ZONE ... does not look like a zone` | The zone was typed wrong | Copy "Lab Zone" from the panel, for example `europe-west1-c` |
| Task 1 stays 0/10, or `Repository "gcr.io" not found` | The `gcr.io` registry repo is missing | Run Step 2's `gcloud artifacts repositories create ...`, rebuild, verify with `list-tags` |
| `❌ Image not found` after a build | The build failed or used a wrong name | Scroll up for the build error, check `echo $MONOLITH`, rebuild |
| Cluster create looks stuck | Normal, takes 5 to 10 minutes | Wait. Do not Ctrl+C or rerun. Check with `gcloud container clusters list` in a second tab |
| Cluster create says there are not enough resources | That zone is short of capacity | Wait a minute and run it again. The lab wants your lab zone, so only change zones as a last resort |
| `❌ An IP is missing` | Load balancer still being created, or the service was not created | Run `kubectl get services`. If an IP shows `<pending>`, wait and run the IP block again. If a service is missing, redo its `create` and `expose` commands |
| `Could not resolve host: api` | `ORDERS_IP` or `PRODUCTS_IP` is empty | Run the Task 4 IP block again and wait for `✅ Both IPs found` |
| `gcr.io//...` in a command | `GOOGLE_CLOUD_PROJECT` is empty | Run step 1.2 again |
| Wrong project in Cloud Shell | Signed in with the wrong account | Use the student account, then `gcloud config set project PROJECT_ID_FROM_THE_LAB_PANEL` |
| `kubectl` cannot connect | Credentials lost | `gcloud container clusters get-credentials $CLUSTER --zone $ZONE` |
| Pod shows `ImagePullBackOff` | Image missing or name mismatch | `gcloud container images list --repository=gcr.io/${GOOGLE_CLOUD_PROJECT}` and rebuild the missing one |
| `❌ .env is missing an IP` | The IP variables were empty when you wrote it | Redo the Task 4 IP block, then run the Task 5 block again |
| Frontend loads but Products/Orders pages are empty | `.env` had wrong IPs when you built | Fix `.env`, run `npm run build`, rebuild the frontend image, and redeploy |
| `already exists` on create | You ran it before | Skip that command |
| Check my progress still red | Names or ports differ from the lab | Run `kubectl get deployments` and `kubectl get services`, compare with your lab, wait 20 seconds, click again |
