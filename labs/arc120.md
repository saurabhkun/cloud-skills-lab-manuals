## Step 1: Open Cloud Shell and set variables

1. Open the lab in an **Incognito** window and sign in with the **student account** shown in the lab panel.
2. Click **Activate Cloud Shell** (top right of the console).
3. Run the following, replacing `REGION_HERE` and `ZONE_HERE` with **your** values:

```bash
export PROJECT_ID=$(gcloud config get-value project)
export REGION=REGION_HERE      # e.g. us-west1
export ZONE=ZONE_HERE          # e.g. us-west1-b
gcloud config set compute/region $REGION
gcloud config set compute/zone $ZONE
echo $PROJECT_ID $REGION $ZONE
```

Check that all three values print correctly before continuing. If `PROJECT_ID` is empty, run `gcloud config set project YOUR_PROJECT_ID`.

> Cloud Shell variables are lost if the session reconnects. If a later command complains about an empty value, re-run this step.

## Task 1: Create a Cloud Storage bucket

The bucket name must be exactly `PROJECT_ID-bucket`, and the location must be **US multi-region**.

```bash
gcloud storage buckets create gs://${PROJECT_ID}-bucket --location=US
```

Click **Check my progress** for Task 1.

## Task 2: Create the VM, create the disk, attach the disk

### 2.1 Allow HTTP traffic

This is what the console's "Allow HTTP traffic" checkbox does. If the command says the rule already exists, skip it.

```bash
gcloud compute firewall-rules create default-allow-http \
  --allow=tcp:80 \
  --target-tags=http-server \
  --source-ranges=0.0.0.0/0
```

### 2.2 Create the VM

Match the values to your Task 2 table.

```bash
gcloud compute instances create my-instance \
  --zone=$ZONE \
  --machine-type=e2-medium \
  --boot-disk-size=10GB \
  --boot-disk-type=pd-balanced \
  --image-family=debian-12 \
  --image-project=debian-cloud \
  --tags=http-server
```

**If your lab uses a different image**, change `--image-family` and `--image-project`:

| Image shown in lab | `--image-family` | `--image-project` |
|--------------------|------------------|-------------------|
| Debian GNU/Linux 12 (bookworm) | `debian-12` | `debian-cloud` |
| Debian GNU/Linux 11 (bullseye) | `debian-11` | `debian-cloud` |
| Ubuntu 22.04 LTS | `ubuntu-2204-lts` | `ubuntu-os-cloud` |
| Ubuntu 24.04 LTS | `ubuntu-2404-lts-amd64` | `ubuntu-os-cloud` |

To list available families: `gcloud compute images list | head -30`

### 2.3 Create and attach the persistent disk

```bash
gcloud compute disks create mydisk --size=200GB --zone=$ZONE
gcloud compute instances attach-disk my-instance --disk=mydisk --zone=$ZONE
```

Click **Check my progress** for Task 2.

### If the Task 2 check fails

```bash
gcloud compute instances describe my-instance --zone=$ZONE
```

Confirm all of these appear in the output:
- `machineType` ends with `e2-medium`
- `tags` includes `http-server`
- `disks` lists both the boot disk and `mydisk`

## Task 3: Install NGINX

### 3.1 SSH into the VM

```bash
gcloud compute ssh my-instance --zone=$ZONE
```

Press **Enter** at the passphrase prompts. Authorize if asked.

### 3.2 Install and verify (inside the VM)

```bash
sudo apt update
sudo apt install nginx -y
sudo systemctl status nginx
```

You should see **`active (running)`**. Press `q` to exit the status view, then type `exit` to leave the VM.

Click **Check my progress** for Task 3.

---

## Test the web server

1. Go to **Compute Engine > VM instances**.
2. Click the **External IP** link in the `my-instance` row, or open `http://EXTERNAL_IP/` in a new tab.
3. Use **`http://`**, not `https://`.
4. You should see **"Welcome to nginx!"**.

## Troubleshooting

| Problem | Fix |
|---------|-----|
| `gs:///...` or an empty value in a command | Variables were lost. Re-run Step 1. |
| Zone or image error | Your lab values differ from the examples. Recheck Step 0. |
| Firewall rule already exists | Skip 2.1. Make sure the VM has the `http-server` tag. |
| Bucket name already taken or wrong | Name must be exactly `PROJECT_ID-bucket`. Check with `echo $PROJECT_ID`. |
| Page does not load in the browser | Use `http://`, wait about 30 seconds, and confirm the firewall rule and tag exist. |
| Check my progress says incomplete | Wait a few seconds and click again, then verify with the `describe` command above. |
| Disk attach fails | Make sure the disk and VM are in the **same zone**. |
