## Read this first

### The 4 rules that prevent most mistakes

**Rule 1: Everything runs in Cloud Shell, except creating the API key (Task 1.1), which you do from the Navigation menu.** In Cloud Shell, look at your prompt. It should say `cloudshell`.

| Prompt looks like | You are in |
|-------------------|-----------|
| `student_xx@cloudshell:~ (project-id)$` | ☁️ Cloud Shell (correct for every command in this lab) |

**Rule 2: Copy ONE block at a time.** Paste, press Enter, read the result, then continue.

**Rule 3: Variables disappear.** If Cloud Shell reconnects or you open a new tab, run Step 1 again, then re-export `API_KEY` (Task 1.1) and run the image block from Task 1.2. If a command shows an empty value (like `gs:///`), that is the reason.

**Rule 4: Check the response file before uploading.** The commands print a ✅ or ❌ line for you. If it contains `"error"`, the upload will "succeed" but the task will stay red.

| Task | What | Where |

## Step 1: Open Cloud Shell and set variables

☁️ **CLOUD SHELL**

1. Click the **Activate Cloud Shell** icon (top right, looks like `>_`).
2. Click **Continue** and **Authorize** on any pop-ups.

**Expected:** your project ID, then the same ID followed by `-bucket`.

2. Click **Create credentials** at the top, then choose **API key**.
3. **Copy** the key that appears. Do not add restrictions.

> [!IMPORTANT]
> ✏️ **FILL IN: paste your API key between the quotes.** This is the only value you must type in this lab.

```bash
# ✏️ FILL IN: paste your API key between the quotes
export API_KEY="paste_your_key_here"
```

Now check it. 🔒 **COPY AS IS**:

```bash
# 🔒 COPY AS IS
```

### 1.2 Find the image name

The bucket already has one image in it. This finds it for you:

```bash
# 🔒 COPY AS IS
IMG_URI=$(gcloud storage ls gs://${BUCKET}/ | grep -iE '\.(jpg|jpeg|png|gif|bmp|webp)$' | head -1)
export IMG=${IMG_URI#gs://${BUCKET}/}
if [ -z "$IMG" ]; then echo "❌ No image found. See the backup step below."; else echo "✅ Image: $IMG"; fi
```

**Expected:** a `✅` line with your image name, like `something.jpg`.

> [!IMPORTANT]
> ✏️ **FILL IN (only if you saw ❌ above):** list the bucket, find the image name yourself, and type it between the quotes.

```bash
# 🔒 COPY AS IS: shows what is in the bucket
gcloud storage ls gs://${BUCKET}/
```

```bash
# ✏️ FILL IN: replace IMAGE_NAME with the exact file name (letters, capitals and extension)
export IMG="IMAGE_NAME"
echo "Image: $IMG"
```

### 1.3 Make the image public

```bash
# 🔒 COPY AS IS: tries the usual way first, then the bucket-wide way if that is blocked
gcloud storage objects update gs://${BUCKET}/${IMG} --add-acl-grant=entity=allUsers,role=READER \
  || gcloud storage buckets add-iam-policy-binding gs://${BUCKET} --member=allUsers --role=roles/storage.objectViewer
```

## Task 2: Create `request.json`

☁️ **CLOUD SHELL**

The lab's template is not valid JSON as printed (`"type":` has no value or comma), so use this finished version. It already includes your bucket and image (Task 3's first update) and the first method, `TEXT_DETECTION`:

```bash
# 🔒 COPY AS IS (paste the whole block at once)
cat > request.json <<EOF
{
  "requests": [
    {
      "image": {
        "source": {
          "gcsImageUri": "gs://${BUCKET}/${IMG}"
        }
      },
      "features": [
        {
          "type": "TEXT_DETECTION",
          "maxResults": 10
        }
      ]
    }
  ]
}
EOF
```

Check it. The `gcsImageUri` line should show your real bucket and image, not empty:

```bash
# 🔒 COPY AS IS
cat request.json
```

## Task 3: Call the Vision API

☁️ **CLOUD SHELL**

### 3.1 Text detection

```bash
# 🔒 COPY AS IS
curl -s -X POST -H "Content-Type: application/json" --data-binary @request.json \
  "https://vision.googleapis.com/v1/images:annotate?key=${API_KEY}" -o text-response.json
head -c 400 text-response.json; echo
grep -q '"error"' text-response.json && echo "❌ The response has an error. Read it above." || echo "✅ No error in text-response.json"
```

**Expected:** a `✅` line and `textAnnotations` in the output, not an `error`.

Upload it to your bucket:

```bash
# 🔒 COPY AS IS
gcloud storage cp text-response.json gs://${BUCKET}
```

Click **Check my progress**.

### 3.2 Landmark detection

Change the method in the same file, then call again:

```bash
# 🔒 COPY AS IS
sed -i 's/TEXT_DETECTION/LANDMARK_DETECTION/' request.json
cat request.json
```

The `type` line should now say `LANDMARK_DETECTION`.

```bash
# 🔒 COPY AS IS
curl -s -X POST -H "Content-Type: application/json" --data-binary @request.json \
  "https://vision.googleapis.com/v1/images:annotate?key=${API_KEY}" -o landmark-response.json
head -c 400 landmark-response.json; echo
grep -q '"error"' landmark-response.json && echo "❌ The response has an error. Read it above." || echo "✅ No error in landmark-response.json"
```

**Expected:** landmark results, or a nearly empty response like `{ "responses": [ {} ] }` if no landmark is found. That is a normal result, so upload it anyway.

Upload it:

```bash
# 🔒 COPY AS IS
gcloud storage cp landmark-response.json gs://${BUCKET}
```

## Troubleshooting

| What you see | Why | Fix |
|--------------|-----|-----|
| `Project:` is blank in Step 1 | Cloud Shell has no project set | Run `gcloud config set project PROJECT_ID_FROM_THE_LAB_PANEL`, then Step 1 again |
| `gs:///` or an empty value | Variables were lost | Re-run Step 1, re-export `API_KEY` (1.1), then run the image block (1.2) |
| Response says `API key not valid` | The new key is not active yet, `API_KEY` is empty, or the key was pasted wrong | Wait a minute, run `echo ${API_KEY:0:8}`, paste the key again in 1.1 if it is blank or wrong, then repeat the curl |
| `❌ API_KEY is not set` | The placeholder was not replaced | Paste your real key in the `API_KEY` line in 1.1 and run it again |
| Response says `has not been enabled` | The Vision API is off in this project | In Cloud Shell run `gcloud services enable vision.googleapis.com`, wait 30 seconds, retry the curl |
| `❌ No image found` in 1.2 | The image has an unusual extension or the bucket is empty | Use the ✏️ FILL IN backup in 1.2 with the exact name shown by `gcloud storage ls` |
| Response mentions the image URI, permission, or 403 | Image is not public yet | Redo 1.3 and confirm `echo $IMG` matches the real name |
| `request.json` shows an empty `gcsImageUri` | `BUCKET` or `IMG` was empty when you created the file | Set both variables again, then recreate `request.json` |
| Landmark response is almost empty | No landmark found in the image | Normal. Upload it anyway |
| Check my progress stays red | Checker is slow, or the file has an error | Look for the `✅` lines, wait 20 seconds, click again |
